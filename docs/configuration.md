# Configuration

All configuration is environment-based. In production the installer writes
three separate files under `/etc/ihs-torrent-manager/` (mode `640`, owned by
`root:ihs-torrent-manager`):

| File | Used by | Notable contents |
|---|---|---|
| `app.env` | `ihs-torrent-manager.service` | DB path, download dir, session secret, qBittorrent host/credentials |
| `worker.env` | `ihs-torrent-manager-worker.service` | DB path, download dir, qBittorrent host/credentials, sync interval |
| `portal.env` | `ihs-torrent-manager-portal.service` | DB path, download dir, portal session secret — **no qBittorrent credentials** |

For local development, `.env.example` documents the same variables in one
place; copy it to `.env` and adjust as needed.

## Common variables

| Variable | Default | Description |
|---|---|---|
| `DATABASE_PATH` | — (required) | Path to the SQLite database file |
| `TORRENT_DOWNLOAD_DIR` | — (required) | Root directory for all torrent data; every file operation is confined here |
| `DISK_WARNING_THRESHOLD_PERCENT_FREE` | `20` | Below this % free, the dashboard shows a warning |
| `DISK_CRITICAL_THRESHOLD_PERCENT_FREE` | `10` | Below this % free, the dashboard shows critical |
| `DISK_BLOCK_THRESHOLD_PERCENT_FREE` | `5` | Below this % free, new torrent uploads are rejected |

Disk thresholds can also be changed at runtime from **Settings** in the
management panel (admin only) — no restart required.

| Variable | Default | Description |
|---|---|---|
| `NOTICE_FILE_PATH` | unset | Path to a plain-text access-warning banner shown on **both** login pages. Unset, or a missing/empty file, simply means no banner. |

The installer creates `/etc/ihs-torrent-manager/notice.txt` from
[`config/notice.txt`](../config/notice.txt) on first install (substituting
the organization name you provide), and points both `app.env` and
`portal.env` at it. Edit that file anytime — no rebuild or restart
required, it's read fresh on every page load — to change the wording or
turn it off (empty the file). Upgrades and repairs never overwrite an
existing `notice.txt`, only a fresh install creates one.

## Management panel (`app.env`)

| Variable | Default | Description |
|---|---|---|
| `APP_PORT` | `3000` | HTTP port |
| `APP_HOST` | `127.0.0.1` | Bind address — keep on localhost if you're using a reverse proxy |
| `SESSION_SECRET` | — (required) | Random secret signing session cookies; generated by the installer |
| `COOKIE_SECURE` | `false` | Set `true` once served over HTTPS — cookies become `Secure` |
| `TRUST_PROXY` | `false` | Set `true` when behind nginx/Caddy so client IPs and `Secure` cookies work correctly |
| `MAX_UPLOAD_SIZE_BYTES` | `10485760` (10 MB) | Max accepted `.torrent` file size |
| `TORRENT_HOST` | — (required) | qBittorrent WebUI base URL, e.g. `http://127.0.0.1:8080` |
| `TORRENT_USERNAME` / `TORRENT_PASSWORD` | — (required) | qBittorrent WebUI credentials (generated by the installer) |

## Background worker (`worker.env`)

Same `TORRENT_HOST`/`TORRENT_USERNAME`/`TORRENT_PASSWORD` as above, plus:

| Variable | Default | Description |
|---|---|---|
| `WORKER_SYNC_INTERVAL_MS` | `5000` | How often the worker polls qBittorrent and updates the database |

## Download portal (`portal.env`)

| Variable | Default | Description |
|---|---|---|
| `PORTAL_PORT` | `3001` | HTTP port |
| `PORTAL_HOST` | `127.0.0.1` | Bind address |
| `PORTAL_SESSION_SECRET` | — (required) | Independent session secret from the panel's |
| `COOKIE_SECURE` / `TRUST_PROXY` | `false` | Same semantics as the panel |

The portal's actual login password is **not** an environment variable — it
is Argon2id-hashed and stored in the database (`settings` table, key
`portal_password_hash`), settable from the installer or from **Settings**
in the management panel. This keeps the one secret that changes most often
out of a file you'd otherwise have to redeploy to rotate.

## qBittorrent

The installer writes `qBittorrent.conf` with `WebUI\Address=127.0.0.1`, so
the WebUI is never reachable from outside the host — the app and worker
reach it over localhost only. Its username/password are randomly
generated during install and stored only in `app.env`/`worker.env`, never
in the portal's environment.

If you need to reach the qBittorrent WebUI directly for debugging, use an
SSH tunnel rather than opening its port:

```bash
ssh -L 8080:127.0.0.1:8080 user@your-server
# then browse to http://127.0.0.1:8080 locally
```
